# Hotel Booking Pipeline

Postgres + dbt + Airflow (Docker) pipeline built on the [Hotel Booking Demand](https://www.kaggle.com/datasets/jessemostipak/hotel-booking-demand) dataset.

Builds on the dataset and cleaning logic explored in [Hotel_Booking_Analysis](https://github.com/JBaptisteAll/Hotel_Booking_Analysis), to build a productionized pipeline, orchestrated with Docker.

## Stack
- Postgres (data warehouse)
- dbt (transformation, medallion architecture: seed → staging → mart)
- Airflow (orchestration)

## Data Quality Notes

### Missing native booking ID
The Kaggle Hotel Booking Demand dataset does not include a unique booking
identifier — a known limitation of this public dataset.

To investigate whether a reliable composite business key could be derived,
a surrogate key was generated by hashing 15 columns (hotel, arrival_date,
lead_time, adr, agent, country, reservation_status_date, booking_changes,
reserved_room_type, children, adults, nights_week, nights_weekend,
market_segment, days_in_waiting_list).

**Result:** out of 119,390 rows, only 84,911 produced a unique hash (~29%
of rows share an identical combination across all 15 columns). This confirms
the dataset lacks sufficient granularity for a trustworthy individual booking
key, likely due to group/block bookings sharing identical attributes.

**Decision:** `stg_bookings` now exposes two distinct columns:
- `booking_id`: a technical row identifier (`ROW_NUMBER()`), used as the
  primary key for dbt tests and joins. No business meaning.
- `duplicate_check_hash`: the surrogate key described above, kept for future
  data quality exploration, not used as a key.
